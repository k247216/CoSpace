# 演示与简历表述

## 五分钟演示

准备两个独立浏览器会话、管理员和提交人账号，以及小型测试文件。

1. 展示个人与团队容量条，说明已用和预占分别代表什么。
2. 管理员创建收集，选择两位提交人；一人提交，另一人不交。
3. 展示提交人与文件清单，再切换团队文件的普通/收集筛选。
4. 下载文件比较内容，向指定账号创建分享，再撤销并用后续请求验证拒绝。
5. 展示上传任务重放验证结果：相同任务不重复登记、不重复计费；说明初始化限流的 429。
6. 打开原始性能 JSON 与测试报告，解释环境、样本量、P95、跳过项和未验证范围。

错误处理演示优先使用自己的测试任务：暂停分片后重新选择同一文件续传；在签名过期后重新签发；上传未完成时取消并核对预占。不要为了演示故障停止共享数据库或删除真实用户文件。

## 可选简历表述

项目名：**CoSpace｜团队文件存储与交付系统**。

- 基于既有文件管理底座完成 Java 21 / Spring Boot 4、Vue 3 升级及团队业务改造，支持角色隔离、指定接收人分享、多人文件收集与提交追踪。
- 设计可恢复上传任务与容量预占，接入私有 OSS 分片直传，处理重试、取消、重复完成和权限变化；以数据库事务、状态核对和后台补偿维护文件、对象与容量一致性。
- 将物理回收改为数据库 Outbox 与 RocketMQ 异步清理，保留失败记录、重投和引用复核；完成 212 项真实依赖回归及 18 项前端上传检查。

性能数据按需要补一句：2 vCPU / 8 GiB、同机客户端、200 条目录项、每档 300 请求、前后各三轮，16 并发 RPS 中位数 117.00→170.15，7,200 请求业务错误为 0。必须能解释低并发波动与统计限制，不把它写成公网最大承载量。

## 需要能回答的问题

- 为什么分片成功不能直接计数，Bitmap 与数据库分别记录什么？
- 数据库事务不能覆盖云存储，完成结果未知时如何判断重试动作？
- 为什么先预占容量，取消和失败时由谁释放？
- 文件引用与物理对象怎样分离，消息重复、消费者失败后如何恢复？
- 移除成员与上传完成谁先锁什么，哪一刻决定是否允许入库？
- 为什么团队读取不需要空间排他锁，撤销权限对已开始下载如何生效？
- 收集记录为什么保留快照，普通上传和收集来源如何关联？
- 403、429、CORS、502 与端口超时分别看哪层证据？

先沿实际请求读代码，再解释一致性边界。不要使用未实现的在线编辑、多实例容灾、完整监控或大规模生产经验作为项目能力。
