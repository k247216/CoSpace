# 发布期间的故障记录

以下是实际发布与联调问题，不代表高流量生产事故。

## MQ 建主题命令退出 0，但主题不存在

现象：本机真实依赖回归通过，GitHub CI 的两项 RocketMQ 交付测试超时，任务停在 PENDING。生产者日志显示 `No route info of this topic`。

定位：先看失败步骤，再补查前面的建主题日志。Broker 尚未就绪时，MQAdmin 的 updateTopic 打印连接失败，但 Java 命令仍返回 0；原先用退出码判断的 shell 因而误认为主题已创建。后续 Broker 启动成功也不会补做那次创建。

修复：环境准备在有限次数内重复创建并查询 topicRoute，以路由包含预期 broker 地址作为就绪条件，超时显式失败。业务任务不改成忽略错误，也不放宽测试断言。

复核：重新执行完整 CI，必须由真实 Broker 消费完成、重复消息无害及失败后重投测试通过来确认，不能只看启动日志。

## 空库初始化因挂载权限失败

现象：已有数据库部署正常；从全新卷启动时 MySQL 健康检查一直失败。

定位：隔离出空卷、无网络的 MySQL 容器，读取初始化日志，发现入口脚本读取 schema.sql 报 Permission denied。严格 umask 使宿主机文件仅创建者可读，而容器使用 mysql 用户执行初始化。

修复：只给 schema、容器配置和静态资源这些非敏感挂载补读取权限；.env 继续限制为 0600。增加独立 Compose 冒烟检查，从新卷验证上传、下载、重放与容量清理。

复核：空库与本地存储闭环通过，清理测试项目的容器和卷；现有业务卷和应用依赖不受影响。

## HTTP 可达，HTTPS 超时

现象：证书签发、服务器回环 HTTPS 返回 200，但普通手机网络打不开，公网 80 返回 308 后跳向不可达的 443。

定位：区分服务监听、主机防火墙和云安全组。服务器 443 正在监听，UFW 未启用；这不能证明云入站规则已允许。当前请求到达与否需要抓包以及有效 NSG 规则共同验证。

处理：补充 Azure TCP443 入站允许规则后，公网 HTTPS 返回 200。浏览器通过公开地址完成 OSS 上传、鉴权下载、内容比对、彻底删除与容量归零验证。
