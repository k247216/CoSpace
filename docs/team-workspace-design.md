# CoSpace 团队空间设计

2026-11-24。团队业务作为本轮最后一个功能阶段。验收通过后进入独立仓库、演示部署与简历说明阶段。

## 实施边界与当前进度

团队空间、四类角色、团队文件树、共享容量、上传权限复核、指定接收人分享、文件收集已接入现有链路。主实现位于 `modules.workspace`，上传字节仍复用原有分片接收或 OSS 直传，正式对象、配额和 Outbox 清理继续使用原生命周期。

本轮采用兼容迁移。个人空间沿用已有 `user_id` 文件树、个人账户与个人分享。团队文件新增 `workspace_id`，`create_user` 记录操作者，旧归属列 `user_id=0` 明确标记团队记录，个人正数用户 ID 查询无法匹配。团队任务保留真实发起人并记录空间及资格版本。团队预占有独立明细，容量存于空间行，复用 `UserSpaceService` 的预占与结算入口分派到对应账户。此次升级通过增量列和新表落地，未批量改写个人数据的所有权或容量。

团队根目录以空间 ID 表示。文件节点的父目录链必须最终到达该根，跨空间的目录 ID 会被拒绝。团队目录递归回收时记录直接回收来源，恢复目录只恢复该次目录删除带入回收站的内容，之前已单独删除的子节点继续留在回收站。彻底删除释放逻辑容量，再由原物理引用判定和 Outbox/RocketMQ 删除对象。

团队默认总容量取服务端配置 `rpan.workspace.default-total-bytes`，客户端创建空间只能指定名称。邀请或修改成员角色需要当前空间治理权限，管理员不能改动所有者及其他管理员，不能把成员提升为管理员。停用和再次邀请均保留同一成员行并递增资格版本，重复相同角色的启用请求保持幂等。收集任务同时记录邀请代次和成员资格快照，撤销后重新邀请也不能恢复旧任务。

启用开关为 `rpan.workspace.enabled`。已有环境按顺序应用 `20261124_workspace_governance.sql`、`20261125_workspace_files.sql`、`20261125_workspace_sharing.sql`、`20261125_workspace_collections.sql`。新库的 `db.sql` 已包含建表。发布包携带增量 SQL，Azure 的容器开关映射为 `COSPACE_WORKSPACE_ENABLED`。

2026-11-25 的隔离回归包含真实 MySQL 的两人抢最后容量、撤权先提交和登记先提交两个并发时序。浏览器使用五个账号完成两个空间的访问隔离、页面上传、只读下载、分享撤销，以及成员和外部受邀人分别从收集页提交。文件、提交记录和容量核对一致。Azure 使用真实 OSS 重复执行交付，并通过认证 HEAD 核对三个团队对象和一个个人对象均已删除，个人页面的上传、下载、回收和配额也复验通过。

## 收集创建与受邀者入口

管理员在团队空间点击“新建收集”，独立表单填写名称、截止时间、文件限制，确认当前归档目录并多选提交人。默认可选当前团队有上传资格的成员；外部账号通过完整用户名或用户 ID 精确查找后加入，不能模糊枚举外部账号。批量创建至少选择一人、最多 100 人，重复 ID 去重。数据库事务中创建任务并写入全部邀请，任意账号不存在或资格无效则全部回滚。

提交人在侧栏“我的收集”查看收到的任务，页面显示来源团队、截止时间、状态和自己的已提交数，可直接进入提交，无需另发链接。列表从现有邀请关系查询，不新增通知或消息系统。登录打开页面或点击刷新即可看到最新邀请。邀请只授权该收集任务和固定归档目录，不授予团队浏览权限。用户 ID 始终作为字符串传输。

管理弹窗列出已邀请用户，可追加多位提交人、逐个撤销或关闭收集。未提交过的用户撤销后不再出现在受邀列表；已提交过的用户保留带撤销状态的历史入口，只能查询自己的提交结果。只读、离队、关闭和到期均会令提交入口不可用，上传签发与登记的服务端资格复核保持不变。受邀列表按当前用户 ID 查询，邀请表增加以 `user_id` 开头的索引。

## 提交进度与文件来源

管理员按受邀人员查看已提交或未提交、文件数量、文件名和最近提交时间。提交结果同时保留上传时文件名和大小快照，文件改名或彻底删除后仍能追溯。正常文件树显示普通上传或收集任务名称，搜索和目录移动后来源仍由逻辑文件 ID 的提交关联确定。来源不改变原逻辑配额结算和物理对象引用规则。

界面采用米白、深绿和简笔画的统一 CoSpace 风格。团队功能按文件、收集任务、成员和分享分区，收集详情与管理弹窗复用报表。页面与验证说明见 [前端设计](frontend-design.md)。

## 交付范围

一次团队资料交付覆盖四种团队角色和外部受邀人。所有者创建空间并分配角色，管理员创建收集并指定提交人，团队成员和受邀外部用户分别提交，管理员在目标目录查看资料，只读成员可以查看和下载，另一空间的成员即使知道资源 ID 也无法访问。外部提交者可查看自己的提交结果。

现有个人接口先保留。团队操作通过显式的空间路由进入服务，上传传输方式由任务记录的存储配置决定。团队交付可以使用已验证的 Azure 中转链路，浏览器直传启用后沿用同一套业务授权和结算。首版关闭跨空间复制、移动和分享转存。

## 数据归属与迁移

| 数据 | 设计 |
| --- | --- |
| 工作空间 | 个人空间由现有用户 ID 映射，`workspace_id` 标识团队空间。每位用户只有一个个人空间，团队以空间 ID 表示根目录并有一个所有者。首版不开放所有者转让或删除空间，避免未定义的资料交接和销毁行为。 |
| 成员关系 | 以 `(workspace_id, user_id)` 唯一定位，保存角色和启用状态。移除改为停用，保留可加锁的行和操作者记录。 |
| 文件节点 | 给 `r_pan_user_file` 增加 `workspace_id`，保留 `create_user` 和 `update_user`。个人接口仍按当前用户映射个人空间，团队节点的旧 `user_id` 为 0。团队目录树、搜索、回收站和下载按空间过滤，检查父目录与祖先都属于同一空间。物理对象和引用生命周期沿用现有表。 |
| 上传与容量 | 任务以现有 `user_id` 记录发起者，并以 `workspace_id` 记录归属，沿用业务 `uploadId` 和固定对象键。个人账户沿用原表，团队空间行保存容量。预占由任务关联空间账户，初始化唯一键包含空间、操作者与 `request_id`。 |
| 分享 | 个人分享沿用原表，团队分享独立记录空间、接收人、到期和撤销信息。创建者仍保留为审计字段，由团队空间继续管理分享。 |
| 收集 | 收集任务记录空间、目标目录、截止时间、状态和文件限制。邀请按 `(collection_id, user_id)` 管理。提交有独立记录，`upload_id` 唯一，关联提交人、空间和已登记文件。 |

本轮通过增量迁移增加团队字段和新表，个人空间继续由现有用户 ID 映射。原先拟议的个人数据批量回填由兼容映射替代，迁移时核对已有目录、分享和容量不变量，再开放团队入口。

- 每位用户的既有根目录和个人账户保留，个人节点与父目录归同一用户。团队节点与父目录归同一团队，个人分享继续使用原授权规则。
- 每个空间的已用容量等于仍保留的逻辑文件计费字节总和，含回收站。预占等于仍为 `RESERVED` 的明细总和。核对活动任务、预占和历史引用，无差异才切换。
- 先以团队入口关闭状态回归个人空间。开放团队写入后，回退用仍能识别团队数据的版本，通过开关暂停新建团队业务。旧构建仅在没有团队写入或已完成数据迁回的窗口使用。

## 权限矩阵

| 操作 | 所有者 | 管理员 | 成员 | 只读 | 外部受邀人 |
| --- | --- | --- | --- | --- | --- |
| 空间设置、分配管理员 | 是 | — | — | — | — |
| 管理成员和只读角色 | 是 | 是 | — | — | — |
| 浏览、搜索、预览、下载空间资料 | 是 | 是 | 是 | 是 | — |
| 上传到团队目录 | 是 | 是 | 是 | — | — |
| 移动、重命名、删除、恢复自己的资料 | 是 | 是 | 是 | — | — |
| 改动其他成员资料或移动、删除非空目录 | 是 | 是 | — | — | — |
| 创建和撤销团队分享、创建和关闭收集 | 是 | 是 | — | — | — |
| 向指定收集提交、查自己的提交结果 | 受邀时 | 受邀时 | 受邀时 | — | 受邀时 |

管理员不能升任所有者或操作所有者及其他管理员的角色。成员管理自己的条目以 `create_user` 判断。非空目录由管理员操作，防止成员通过移动、删除目录间接影响他人文件。目录移动须校验源、目标及祖先，禁止移动到自身子树。收集页只授权指定任务与目的目录，不能列出团队目录树或下载其他人的提交。

每个入口都先从登录信息取得操作者，再按路由的空间和输入资源校验。文件、目录、上传任务、回收站查询同时匹配空间 ID 与资源 ID。团队链接通过专用已登录入口访问，老个人接口只解析个人空间里的资料。分享下载逐请求检查接收人、有效期、撤销和源文件状态。撤销影响之后的请求，已开始的流式下载可以结束。

## 上传、配额和权限变化

空间账户保存 `total`、`used` 和 `reserved`。初始化先检查目标准入和文件限制，再加锁预占。两个用户争抢最后容量时，共用团队账户行锁和条件更新 `used + reserved + fileSize <= total`。额度不足时，任务和预占均不提交。取消、到期或资格撤销可释放仍处于 `RESERVED` 的明细。回收站中的逻辑文件继续计费，彻底删除时释放已用容量，物理引用归零后才走 Outbox 和 RocketMQ。

团队上传初始化与完成登记使用数据库短事务。团队写入统一按**空间容量行 → 资格行 → 上传任务行 → 文件和目录行**加锁。团队成员关系为普通上传的资格行。收集上传先锁收集任务，再锁邀请行。成员移除、邀请撤销和收集关闭也按相同前缀顺序加锁。长时间的分片和对象 I/O 放在事务外，收尾登记前重新校验资格、截止和目录。

最终登记事务是竞态判定点。资格撤销先提交时，之后的登记必须拒绝。上传任务的预占经取消或到期释放，遗留对象进入清理核对。登记先提交时，文件和提交结果归团队保留。撤销后停止接收或签发新分片请求。上传任务记录初始化时的资格版本，移除成员、降为只读或撤销邀请时递增版本，重新授权也不会恢复已失效的任务。若已发出的短时链接仍能传输，最终登记仍以当前资格为准。

分享、收集和上传均由服务端解析资源归属。提交人不再向上传接口传一个可改写的最终目录，后端从收集记录取目标目录。文件引用、提交记录、容量结算与任务完成状态同事务提交。重试同一 `uploadId` 读取既有提交结果，查询仍按当前请求人的结果查看权限校验。

## 实施顺序与验收

1. **迁移与个人回归。** 先验证增量迁移保留旧记录，再核对目录树、分享和容量账目。覆盖旧文件下载、在途任务续传、回收站恢复和彻底删除。
2. **团队空间与权限。** 接入空间与成员管理、显式空间文件入口、团队配额，以及成员移除和上传登记的并发校验。有两套空间隔离通过后再开放分享。
3. **受控分享。** 验证指定接收人可访问，转发给未授权账户后拒绝，到期和撤销立即作用于后续请求。创建者离队后仍可由团队管理员撤销，源文件进入回收站后停止访问。
4. **文件收集。** 管理员指定目录、提交人、截止与文件限制。成员和外部受邀者分别提交，只读人员浏览归档结果，另一空间成员按原始资源 ID 访问失败。关闭收集后拒绝新的初始化和入库。
5. **真实竞态与对象核对。** 使用独立请求和事务同步点并发争抢最后一段容量，验证只有足额请求成功。分别以移除先提交、登记先提交执行两轮，核对资格、任务状态、预占、已用、文件树和真实 Bucket 中的对象。验证取消和失败后的定时清理，并确认异步彻底删除前后对象状态。

演示交付到此为止。空间转让、审核流、匿名收集、协同编辑和跨空间复制属于后续独立阶段。
