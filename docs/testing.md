## 运行完整回归

先准备仅供测试使用的本机 MySQL 与 Redis，再启动独立 MQ：

```bash
docker compose -f deploy/test/compose.yaml up -d namesrv broker
docker compose -f deploy/test/compose.yaml run --rm topic
export RPAN_TEST_MYSQL_USER=你的测试账号
# 密码通过本机环境注入，不要写进 Git 历史
export RPAN_TEST_MQ_NAMESERVER=127.0.0.1:19876
bash scripts/check-backend-regression.sh -B -ntp
```

必需环境变量 `RPAN_TEST_MYSQL_PASSWORD`，允许空字符串；可选 `RPAN_TEST_MYSQL_PORT` 默认 3306、`RPAN_TEST_REDIS_PORT` 默认 6379、`RPAN_TEST_REDIS_PASSWORD`。MySQL 用户须可创建和删除前缀为 `r_pan_cleanup_test_` 的测试库。Redis 使用 DB15。脚本在退出时清理自身库和文件，不会替你清理外部环境。

结束后：`docker compose -f deploy/test/compose.yaml down -v`，仅针对该独立测试项目。

CI 使用临时 MySQL、Redis 和 RocketMQ 容器，并上传 Surefire XML。CI 中的固定数据库口令仅供该次临时服务，不是部署凭证。

## 浏览器验收清单

使用独立浏览器会话分别登录管理员、成员、只读者、外部受邀者。注册两个空间，核验跨空间访问拒绝。

1. 个人及团队各上传一份文件，下载并比较字节，再彻底删除，核对容量。
2. 创建收集并多选两位接收人：接收人能发现邀请，提交后管理员区分已交、未交、文件名和大小。
3. 普通上传与收集文件分别筛选。改名与彻底删除后，收集报表保留原始提交快照，已删除文件不能下载。
4. 指定接收人的分享不能被其他登录者使用；撤销后新下载请求拒绝。
5. 上传期间撤销资格，后续签发和入库拒绝，预占最终释放。
6. 首页检查 1440×900、1366×768、1280×720、1024×600、390×844、375×667：无滚动，所有入口都在可见区域内。其他列表和报表允许必要滚动。

本次发布在真实 Azure 后端和浏览器中复验团队收集、提交报表、来源筛选、下载字节与清理账目。公网 TLS 可达性单独验证，不能用 SSH 隧道验收代替访客网络验收。
